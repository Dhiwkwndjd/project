```
Выполни БЛОК 3: новая функция — страница редактирования профиля пользователя.

## Задача 3.1. Редактирование личного кабинета

Файл: frontend/src/pages/ProfilePage.jsx

Если страница профиля уже находится в другом файле, например frontend/src/components/ProfilePage.jsx, используй существующий файл и не создавай второй компонент без необходимости. При необходимости сохрани совместимость с текущими маршрутами в App.jsx.

### 1. Отображение профиля

На странице отображай:
- имя пользователя (username);
- электронную почту (email);
- описание профиля (bio);
- аватар пользователя (avatar_url).

Загружай данные через существующий AuthContext или API-клиент Axios. Не создавай отдельный Axios-клиент.

Если данные пользователя уже загружаются через GET /api/v1/auth/me/, используй существующий механизм.

### 2. Отображение аватара

- Если avatar_url содержит ссылку, отображай изображение через img.
- Добавь alt с понятным описанием аватара.
- Если ссылка пустая или изображение не загрузилось, отображай стандартную заглушку с нейтральным оформлением.
- При изменении avatar_url обновляй отображаемое изображение.

Не устанавливай дополнительные библиотеки ради аватара.

### 3. Форма редактирования

Добавь форму с полями:

- bio — описание пользователя;
- avatar_url — URL изображения аватара.

Требования:
- Используй useState для хранения значений формы.
- При первоначальной загрузке заполняй поля данными текущего пользователя.
- Добавь кнопку «Сохранить изменения».
- Проверь, что avatar_url является корректным URL, если поле заполнено.
- Во время отправки показывай «Сохранение...» и блокируй повторную отправку.
- Показывай понятное сообщение при ошибке.
- Не перезагружай страницу при отправке формы.

### 4. Сохранение изменений

При отправке формы выполняй:

PATCH /api/v1/auth/me/

Тело запроса:

{
  "bio": "Описание пользователя",
  "avatar_url": "https://example.com/avatar.png"
}

Используй существующий Axios-клиент из frontend/src/api/axios.js. Авторизация должна выполняться через access-токен автоматически.

После успешного ответа:
- обнови данные профиля на странице;
- обнови user в AuthContext, если контекст хранит данные профиля;
- покажи уведомление «Профиль успешно обновлен».

Если сервер вернул ошибку, не показывай уведомление об успехе.

### 5. Всплывающее уведомление

После успешного сохранения показывай уведомление:

«Профиль успешно обновлен»

Сделай его заметным, но ненавязчивым. Уведомление должно исчезать автоматически через несколько секунд. Если в проекте уже есть система уведомлений, используй её. Не добавляй новые библиотеки без необходимости.

### 6. Оформление

Если в проекте используются отдельные CSS-файлы, создай или обнови CSS для страницы профиля.

Сделай:
- аккуратное отображение аватара;
- понятные подписи полей;
- удобные кнопки;
- заметное сообщение об успехе и ошибке;
- адаптацию под мобильные экраны.

Сохрани общий стиль существующего приложения.

### 7. Проверка

1. Проверь корректность импортов.
2. Выполни npm run build в папке frontend.
3. Проверь загрузку данных пользователя.
4. Проверь изменение bio.
5. Проверь изменение avatar_url.
6. Проверь работу заглушки, если аватар отсутствует или не загружается.
7. Проверь появление уведомления только после успешного PATCH-запроса.
8. Убедись, что регистрация, вход, JWT и выход из аккаунта продолжают работать.

Если обнаружишь несовпадение формата ответа API с текущим кодом, изучи backend и внеси минимальные необходимые исправления.

Не выполняй git init, git commit или git push. Не устанавливай Aider.

В конце перечисли изменённые файлы и результаты реально выполненных проверок.
```
