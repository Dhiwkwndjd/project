# 06. ЭТАП 3 — Frontend: формы, роутинг, защищённый профиль

## 🧑 Пользователь

```
Выполни ЭТАП 3: Frontend, формы регистрации и входа, роутинг и защищённая страница профиля.

Работай непосредственно с файлами проекта через терминал. Сначала изучи существующий frontend и API бэкенда. Не переписывай проект целиком. Используй простой React-код, понятный начинающему.

## 1. API-клиент

Создай файл frontend/src/api/axios.js.

Настрой Axios:
- Базовый URL: http://localhost:8000/api/v1/
- Перед каждым запросом проверяй localStorage.
- Если в localStorage есть access-токен, автоматически добавляй заголовок Authorization: Bearer <token>.
- Используй ключ localStorage `access`.
- Обрабатывай ошибки запросов так, чтобы пользователь видел понятное сообщение.

Все запросы к API должны использовать этот клиент.

## 2. Форма регистрации

Создай файл frontend/src/components/RegisterForm.jsx.

Требования:
- Поля username, email и password.
- Используй useState для хранения введённых данных.
- При отправке формы выполни POST-запрос на auth/register/.
- Показывай сообщение об ошибке, если регистрация не удалась.
- При успешной регистрации перенаправляй пользователя на /login/.
- Добавь ссылку на страницу входа.
- Не перезагружай страницу при отправке формы.

## 3. Форма входа

Создай файл frontend/src/components/LoginForm.jsx.

Требования:
- Поля username и password.
- Используй POST-запрос на auth/login/.
- При успешном входе сохрани access и refresh токены в localStorage под ключами `access` и `refresh`.
- После успешного входа перенаправляй пользователя на /profile/.
- При ошибке выводи понятное сообщение.
- Добавь ссылку на регистрацию.

Учитывай, что стандартный SimpleJWT ожидает username и password, если в Django не настроена другая модель авторизации.

## 4. Защищённый маршрут

Создай файл frontend/src/components/ProtectedRoute.jsx.

Требования:
- Если access-токен отсутствует, перенаправляй пользователя на /login/.
- Если токен есть, разрешай отображение вложенной страницы.
- Используй Navigate и Outlet из react-router-dom.
- Не считай наличие токена гарантией его действительности: при ошибке авторизации на странице профиля нужно удалить недействительные токены и перенаправить пользователя на вход.

## 5. Роутинг приложения

Обнови файл frontend/src/App.jsx.

Настрой маршруты с помощью react-router-dom:

- /register/ — регистрация.
- /login/ — вход.
- /profile/ — защищённый профиль.
- / — перенаправление на /profile/, если пользователь авторизован, иначе на /login/.

Создай отдельную страницу профиля, например frontend/src/components/ProfilePage.jsx.

На странице профиля:
- Выполняй GET-запрос на auth/me/ через Axios.
- Отображай username, email и id пользователя.
- Показывай сообщение о загрузке данных.
- Обрабатывай ошибки API.
- Добавь кнопку «Выйти».
- При выходе удаляй access и refresh из localStorage и перенаправляй на /login/.

## 6. Оформление

Если отдельные CSS-файлы уже существуют, используй их. Если нет, создай простое оформление для форм и профиля.

Требования:
- Формы должны быть расположены аккуратно.
- Добавь подписи полей, кнопки и сообщения об ошибках.
- Интерфейс должен быть удобен для просмотра на компьютере и телефоне.
- Не устанавливай дополнительные библиотеки для оформления.

## 7. Проверка работы

1. Убедись, что все импорты корректны.
2. Проверь запуск frontend через npm run dev.
3. Выполни npm run build.

Не изменяй backend без необходимости. Если обнаружишь несовпадение API с заданием, сначала изучи существующие маршруты и внеси минимальные совместимые исправления.
```

### Как запустить frontend

Сначала backend (в отдельном терминале):

```powershell
cd backend
.\venv\Scripts\Activate.ps1
python manage.py runserver
```

Затем frontend:

```powershell
cd frontend
npm run dev
```

Открыть **http://localhost:5173/** → редирект на `/login/` (или `/profile/`, если уже вошёл).
