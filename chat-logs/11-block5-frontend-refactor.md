## Задача 2.1. Axios Interceptor для автоматического обновления токенов

Файл: frontend/src/api/axios.js

Настрой Axios для автоматического обновления access-токена.

Базовый URL:
http://localhost:8000/api/v1/

Токены хранятся в localStorage:
- access
- refresh

Настрой request interceptor:
- Перед отправкой запроса проверяй наличие access-токена.
- Если токен есть, добавляй заголовок Authorization: Bearer <access>.

Настрой response interceptor:
1. Если сервер вернул 401 Unauthorized, проверь, не является ли запрос повторным.
2. Не запускай обновление токена для запросов входа, регистрации и самого обновления токена.
3. Если refresh-токен есть, отправь POST-запрос на auth/refresh/ с телом:
   { "refresh": "<refresh-токен>" }
4. Если сервер вернул новый access-токен, сохрани его в localStorage.
5. Добавь новый access-токен в заголовок Authorization и повтори исходный запрос только один раз.
6. Если refresh-токен отсутствует или недействителен, удали access и refresh из localStorage и перенаправь пользователя на /login/.

Используй отдельный Axios-запрос для обновления токена без повторного срабатывания основного response interceptor.

Обрабатывай ошибки безопасно. Не допускай бесконечного цикла обновления токена. Если несколько запросов одновременно получили 401, постарайся избежать нескольких параллельных запросов на обновление токена.

Сохрани совместимость с существующими импортами API-клиента.

## Задача 2.2. Централизованный AuthContext

Создай файл frontend/src/context/AuthContext.jsx.

Реализуй:
- AuthContext.
- AuthProvider.
- Хранение текущего пользователя в состоянии user.
- Состояние загрузки loading.
- Функции login(username, password), register(data) и logout().

Важно: если существующий проект использует username для входа через стандартный SimpleJWT, сохрани этот формат. Не заменяй username на email без проверки настроек Django.

Функция login:
1. Отправляет POST на auth/login/.
2. Получает access и refresh.
3. Сохраняет оба токена в localStorage.
4. Загружает данные пользователя через GET auth/me/.
5. Сохраняет данные в user.
6. Корректно обрабатывает ошибки и передаёт их форме входа.

Функция register:
1. Отправляет POST на auth/register/.
2. Возвращает результат регистрации.
3. Не сохраняет фиктивные токены и не авторизует пользователя автоматически, если API этого не предусматривает.

Функция logout:
1. Удаляет access и refresh из localStorage.
2. Очищает user.
3. Не оставляет пользователя в состоянии авторизации.

При монтировании AuthProvider:
- Установи loading в true.
- Проверь наличие access-токена.
- Если токен есть, запроси auth/me/.
- Сохрани пользователя при успехе.
- При недействительном токене обработай ошибку и очисти авторизационные данные.
- В конце установи loading в false.

Используй Context Provider, чтобы компоненты могли получать user, loading, login, register и logout.

Файл: frontend/src/App.jsx

Оберни маршруты приложения в AuthProvider. Сохрани существующие страницы регистрации, входа и профиля.

Убедись, что защищённые маршруты учитывают loading и не перенаправляют пользователя до завершения первоначальной проверки авторизации.
